자기소개서

Java/Spring과 Python AI를 연결하는 하이브리드 개발자

제 가장 큰 강점은 연결입니다. 사람과 사람, 사람과 기술, 그리고 기술과 서비스를 연결하며 문제의 본질을 이해하고 해결하는 과정을 좋아합니다.

처음 개발에 관심을 갖게 된 계기는 단순했습니다. 컴퓨터 안에서 명령어 한 줄을 입력하면 동작이 바뀌고, 작성한 코드가 화면과 기능으로 바로 나타나는 과정이 흥미로웠습니다. 게임 제작 영상에서 코드와 명령어에 따라 화면이 바뀌는 모습을 보며, 기술이 눈에 보이는 결과로 이어지는 과정에 자연스럽게 끌렸습니다.

처음부터 개발자의 길이 명확했던 것은 아닙니다. 2020년 인공지능 교육 과정에 도전했고, 이후 머신러닝과 딥러닝을 접해보기도 했지만, 당시에는 기초가 부족해 기술의 구조를 제대로 이해하지 못했습니다. 그래서 한동안 미군 부대 근무와 소방설비 공부를 하며 제 적성을 다시 확인하는 시간을 보냈습니다.

마지막이라는 마음으로 다시 개발 교육에 지원했고, Java와 웹 개발을 배우면서 비로소 이 길이 저에게 맞는다는 확신을 얻었습니다. 이후 AI 심화 과정을 들으며 AI를 서비스 안에서 활용하는 방법에도 관심을 갖게 되었습니다. 단순히 화면에 데이터를 보여주는 것을 넘어, 사용자의 질문을 이해하고 관련 정보를 찾아 답변하는 흐름이 서비스 안에 들어갈 수 있다는 점이 매력적으로 느껴졌습니다.

짧은 기간 동안 AI를 깊게 이해했다고 말하기는 어렵습니다. 하지만 직접 AI 검색 기능을 구현하며 모델 성능뿐 아니라 데이터 구조, 검색 방식, API 연동, 응답 품질까지 함께 고려해야 실제 서비스가 된다는 것을 배웠습니다. 이 경험을 통해 AI를 단순 기능이 아니라 서비스의 문제 해결력을 확장하는 도구로 바라보게 되었습니다.

이 경험을 바탕으로 저는 특정 분야에만 한정된 개발자가 아니라, 웹 서비스와 AI 기술을 연결하고 필요하다면 반도체, 전자, 제조 등 다양한 산업의 문제를 소프트웨어로 해결하는 개발자로 성장하고자 합니다.

프로젝트 문제 해결 경험

PlusHome 가구 쇼핑 및 인테리어 상담 플랫폼 개발
PlusHome 프로젝트는 React, Spring Boot, MyBatis, OracleDB 기반으로 제작되었습니다. 사용자는 가구를 구매하고 인테리어 업체와 상담을 진행할 수 있으며 사업자는 상품과 상담을 관리할 수 있도록 개발했습니다. 저는 메인 화면, 통합 검색, 상품 문의, 추천/숨김, 대본 기반 챗봇 기능을 담당했습니다.

프로젝트를 진행하며 먼저 고민했던 부분은 검색 상태를 어떻게 유지할 것인가였습니다. 초기에는 검색어, 필터, 페이지 정보를 화면 상태로만 관리했기 때문에 새로고침이나 뒤로가기를 하면 사용자가 설정한 조건이 초기화되는 문제가 있었습니다. 이를 해결하기 위해 검색어, 필터, 페이지 정보를 URL QueryString으로 관리하는 구조로 변경했습니다. 화면 진입 시 QueryString을 기준으로 검색 조건을 복원하도록 구현해 새로고침과 URL 공유, 뒤로가기 이후에도 동일한 검색 결과를 유지할 수 있도록 개선했습니다.

또 다른 고민은 추천 상품 숨김 기능의 상태를 어떻게 유지할 것인가였습니다. 초기에는 화면에서만 숨김 상태를 관리했기 때문에 새로고침하거나 다시 로그인하면 숨김 정보가 초기화되었습니다. 이를 해결하기 위해 사용자 ID를 기준으로 숨김 상품 정보를 데이터베이스에 저장하고, 로그인 시 사용자별 숨김 목록을 다시 조회하는 구조로 변경했습니다. 또한 중복 데이터를 제거한 뒤 최신 상태를 저장하도록 구현해 사용자별 추천/숨김 상태가 지속적으로 유지되도록 개선했습니다.

RAG 기반 AI 가구 추천 챗봇
PlusHome에서 AI 추천 기능을 구현하지 못한 아쉬움이 남아 개인 프로젝트로 CNN 기반 이미지 분류와 RAG를 결합한 가구 추천 챗봇을 구현했습니다. Streamlit을 활용해 이미지 업로드부터 추천 결과까지 확인할 수 있는 프로토타입도 함께 제작했습니다.

MobileNetV2 기반 전이학습 모델을 적용하는 과정에서 TensorFlow/Keras 버전 차이로 모델이 정상적으로 로드되지 않는 문제가 발생했고, 호환 가능한 모델을 별도로 생성해 Streamlit 환경에서 사용할 수 있도록 개선했습니다. 또한 로컬 Ollama 운영의 메모리 제약과 API 연결 문제를 확인한 뒤 Gemini API 기반으로 구조를 변경해 이미지 분류, RAG 검색, AI 답변 생성까지 전체 파이프라인을 완성했습니다.

BidMatch AI 기반 나라장터 입찰 공고 추천 서비스 개발
BidMatch 프로젝트는 React, Spring Boot, FastAPI, PostgreSQL(pgvector), Redis 기반으로 구축한 AI 기반 나라장터 입찰 공고 추천 서비스입니다. 자연어 기반 공고 검색 및 탐색, AI 추천/요약, 입찰 자격 자가진단, OCR, RAG 챗봇 기능을 제공하며 Docker와 Jenkins 기반 CI/CD 환경에서 개발했습니다.

프로젝트 초반 어려웠던 점은 기능 구현보다 이미 구축된 시스템 구조를 이해하는 것이었습니다. 이번에는 Docker 환경에서 Nginx, Spring Boot, FastAPI, PostgreSQL(pgvector), Redis로 구성된 아키텍처 위에서 개발을 진행해야 했습니다. 그래서 먼저 React에서 시작된 요청이 Spring Boot와 FastAPI를 거쳐 PostgreSQL과 AI 서버까지 처리되는 전체 흐름과 서비스 간 API 연계 구조를 분석하고, 담당 기능이 서비스에서 수행하는 역할을 파악한 뒤 개발을 진행했습니다.

이후 가장 많은 고민을 하며 개선이 필요했던 부분은 자연어 기반 AI 검색 품질 개선이었습니다. 사용자가 자연어로 검색하면 의미 유사도만으로는 지역, 업무 키워드, 예산 조건이 충분히 반영되지 않아 실제 요구와 맞지 않는 공고가 상위에 노출되는 문제가 있었으며, 오타나 질문 문장이 모호한 경우 제대로 인식하지 못해 엉뚱한 공고를 추천했습니다.

이를 해결하기 위해 검색 파이프라인을 단계적으로 개선했습니다. 검색어에서 지역, 키워드, 예산 조건을 추출해 검색 조건으로 구조화하고, 자모 분해와 유사도 비교를 활용한 지역명 오타 보정을 적용했습니다. 이후 BGE-M3 임베딩으로 의미적으로 유사한 후보 공고를 검색한 뒤 Hybrid 검색을 통한 재정렬을 적용해 검색 조건과 의미 유사도를 함께 반영하도록 개선했습니다.

또한 추천 이유, 조건 일치 여부, 추가 확인이 필요한 요소를 함께 제공해 사용자가 검색 결과를 쉽게 판단할 수 있도록 했으며, AI 응답 실패 시에는 일반 검색으로 전환되는 fallback 로직을 구현해 서비스의 안정성을 높였습니다.

검색 파이프라인을 여러 차례 개선했음에도 다양한 검색 패턴에서는 여전히 한계가 존재한다는 점을 확인했고, GraphRAG와 같은 새로운 검색 기법을 검토하며 AI 검색은 한 번의 구현이 아니라 지속적인 개선과 검증이 필요한 영역이라는 점을 배웠습니다.

2020년 처음 AI를 접했지만 기초가 부족한 상태에서 구현에만 집중하다 보니, 원리를 이해하기보다 따라 구현하는 데 그치는 제 모습을 발견했습니다.

다시 개발을 시작하며 AI 기술 자체를 배우는 것보다 사용자가 실제로 활용할 수 있는 서비스로 연결하고, 웹 백엔드와 AI를 함께 이해하는 개발자가 되는 것을 목표로 했습니다.

Action
Java와 Spring 기반 웹 백엔드를 먼저 학습하며 서비스 구조를 익혔고, 개인 프로젝트에서는 CNN, RAG, LLM을 직접 구현하며 AI를 다시 공부했습니다. 이후 BidMatch 프로젝트에서는 Spring Boot와 FastAPI를 연계한 자연어 검색 기능을 개발하며 AI를 실제 서비스의 기능으로 구현하는 경험을 쌓았습니다.

Result
이 경험을 통해 기술은 목적이 아니라 문제를 해결하기 위한 수단이며, 각각의 기술이 연결될 때 비로소 사용자에게 가치가 전달된다는 점을 배웠습니다. 앞으로도 새로운 기술을 배우는 데 그치지 않고, 기술 간의 연결을 통해 실제 서비스의 가치를 만들어내는 개발자로 성장하고자 합니다.

협업은 같은 목표를 만드는 과정

6개월 과정에서 세 차례 팀장 역할을 맡았고, 심화 과정에서는 팀원으로 프로젝트를 수행했습니다. 두 역할을 모두 경험하며 협업은 단순히 업무를 나누는 것이 아니라, 팀이 같은 목표와 기준으로 움직일 수 있도록 만드는 과정이라는 것을 배웠습니다.

제 첫 프로젝트에서는 모두가 GitHub 협업이 익숙하지 않아 각자 개발한 파일을 수동으로 통합했고, 그 과정에서 작업 범위와 완료 기준이 명확하지 않아 화면 연결 오류, CSS 불일치, 기능 우선순위 충돌이 발생했습니다. 또한 제가 전달한 내용이 팀원마다 다르게 이해되면서 협업에서는 기술보다 같은 기준을 공유하는 것이 더 중요하다는 점을 느꼈습니다.

이후 진행되는 프로젝트들에서는 Notion 및 소통을 적극 활용해 담당 기능, 완료 기준, 남은 이슈를 매일 공유하고, 팀원별 진행 상황을 지속적으로 확인했습니다. 기능 구현 전에는 화면 흐름과 역할 범위를 함께 정리했고, 의견 차이가 생기면 누구의 의견이 맞는지를 판단하기보다 프로젝트 목표와 일정 기준에서 해결 방향을 함께 결정했습니다.

반면 심화 과정의 파이널 프로젝트에서는 팀원으로 참여하며 또 다른 협업을 경험했습니다. 이전에는 반복적으로 진행 상황을 확인하는 것이 다소 번거롭다고 생각하기도 했지만, 팀원이 되어 보니 저 역시 전달받은 내용을 다시 확인하거나 놓치는 경우가 있었습니다. 또한 팀장의 방향과 다른 의견이 있을 때는 무조건 따르기보다, 프로젝트에 도움이 된다고 판단되는 내용은 근거를 정리해 제안하고 최종 결정은 팀의 방향에 맞춰 개발을 진행했습니다.

이 경험을 통해 팀장은 명확한 기준을 만들고 반복적으로 공유해야 하며, 팀원은 자신의 진행 상황과 의견을 적극적으로 공유하고 필요할 때는 근거를 바탕으로 제안하는 역할이 중요하다는 것을 배웠습니다. 결국 협업은 역할을 나누는 것이 아니라 같은 목표를 향해 서로를 연결하는 과정이라고 생각합니다.

협업을 통해 성장하고, 개선으로 완성하다

장점 1. 사람들과 함께 성장하는 협업 능력
익숙한 환경이든 새로운 환경이든 먼저 다가가 대화를 시작합니다. 사람마다 가진 강점을 배우고, 필요한 부분은 함께 고민하며 자연스럽게 협업하는 것을 좋아합니다.

장점 2. 끝까지 개선하는 문제 해결 성향
어렸을 적, 나무를 자르고 못질을 해서 의자를 만들었습니다. 만들고 나서 앉아보니 불편했고, 미관상 좋지 않아 어린 손으로 다시 또 다시 고쳤습니다. 이렇듯 저는 개발에서도 기능이 구현되었다고 담당 업무가 끝났다고 생각하지 않습니다. 사용자의 시선에서 바라보며 원하는 결과를 얻을 수 있는지 끊임없이 고민하며 더 나은 결과를 만들기 위해 노력합니다.

단점 1. 깊이 분석하는 성향
의자를 고치다 손에 가시가 박히기도 했고, 시간 가는 줄 모르고 몰두해 해가 진 뒤에야 작업을 마친 적도 있었습니다. 제가 문제를 분석하게 되면 원인이 무엇인지, 그게 납득이 되는지 끝까지 파고들었습니다. 덕분에 문제를 정확하게 이해하고 해결하는 데 도움이 되었지만, 가끔은 해결하지 못한 채 끝내야 하거나 세부적인 문제에 많은 시간을 할애해야 하는 경우도 있었습니다. 이를 개선하기 위해 작은 문제, 큰 문제 가리지 않고 우선순위를 정하고, 이후 우선순위를 체크하며 시간 관리하는 습관을 들이고 있습니다.

단점 2. 기준이 높아 스스로 만족하기 어렵다
저는 결과물을 제출하기 전에 스스로 납득할 수 있는 수준인지 여러 번 확인하는 편입니다. 이러한 성향 덕분에 완성도를 높일 수 있었지만, 때로는 이미 충분한 결과물도 더 개선하려 하며 기준을 높게 잡는 경우가 있었습니다. 최근에는 사용자가 체감하는 가치와 프로젝트의 목표를 먼저 고려하며, 일정 안에서 가장 큰 효과를 낼 수 있는 개선에 집중하려고 노력하고 있습니다.

문제를 이해하고 해결책을 만들어가다

지난 프로젝트에서 구현하지 못했던 AI 기능을 개인 프로젝트로 직접 구현했고, 이후 새로운 프로젝트에서는 이를 실제 서비스의 자연어 검색 기능으로 발전시키며 AI를 서비스에 적용하는 경험을 쌓았습니다. 이 과정에서 웹 백엔드와 AI 기술이 서로 독립된 영역이 아니라 하나의 서비스를 완성하기 위해 유기적으로 연결되어야 한다는 점을 배웠습니다.

앞으로도 Java/Spring 기반 서비스 개발 경험과 Python/FastAPI 기반 AI 개발 경험을 바탕으로, 비즈니스 로직부터 데이터 처리, AI 연동까지 전체 흐름을 이해하며 다양한 기술을 문제에 맞게 연결하고 실제 가치로 구현하는 개발자로 성장하고자 합니다.
